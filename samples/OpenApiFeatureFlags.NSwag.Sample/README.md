# OpenApiFeatureFlags.NSwag.Sample

A runnable API whose Swagger document is generated by NSwag and respects feature flags. It is the
NSwag counterpart of [`OpenApiFeatureFlags.Sample`](../OpenApiFeatureFlags.Sample), which uses
Swashbuckle, and it is the setup [`docs/nswag.md`](../../docs/nswag.md) describes.

## Run it

```shell
dotnet run --project samples/OpenApiFeatureFlags.NSwag.Sample --urls http://localhost:5182
```

- Swagger UI: <http://localhost:5182/swagger>
- Raw document: <http://localhost:5182/swagger/v1/swagger.json>

## What to look at

The flags live in `appsettings.json` under `FeatureManagement`. With the defaults (all off), the
document is missing everything the flags gate:

- `POST /api/orders/checkout` and the minimal endpoint `GET /api/quote` (`NewCheckout`)
- the `loyaltyPoints` property of `Order`, and part of its `total` description (`LoyaltyProgram`)
- the `scope` parameter of `GET /api/orders/search` and of `GET /api/search`, plus a sentence in
  their summaries (`InternalSearch`)

Flip a flag and request the document again. The quickest way, without editing the file:

```shell
FeatureManagement__NewCheckout=true dotnet run --project samples/OpenApiFeatureFlags.NSwag.Sample --urls http://localhost:5182
```

The escaped `&lt;gate&gt;` fragments in the XML documentation comments are deliberate: NSwag
flattens raw markup, so the escape is what makes a gate survive into the document. The model uses a
`[Description]` attribute for the same reason. Both are measured in
[`docs/nswag.md`](../../docs/nswag.md).
