# OpenApiFeatureFlags.AspNetCore.Sample

A runnable API whose OpenAPI document is generated by the built-in
`Microsoft.AspNetCore.OpenApi` engine and respects feature flags. It is the built-in-engine
counterpart of [`OpenApiFeatureFlags.Sample`](../OpenApiFeatureFlags.Sample), which uses
Swashbuckle, and it is the setup [`docs/aspnetcore.md`](../../docs/aspnetcore.md) describes.

## Run it

```shell
dotnet run --project samples/OpenApiFeatureFlags.AspNetCore.Sample --urls http://localhost:5183
```

- Raw document: <http://localhost:5183/openapi/v1.json>

## What to look at

The flags live in `appsettings.json` under `FeatureManagement`. With the defaults (all off), the
document is missing everything the flags gate:

- `POST /api/orders/checkout` and the minimal endpoint `GET /api/quote` (`NewCheckout`)
- the `loyaltyPoints` property of `Order`, and part of its `total` description (`LoyaltyProgram`)
- the `scope` parameter of `GET /api/orders/search`, plus a sentence in its summary
  (`InternalSearch`)

Flip a flag and request the document again. The quickest way, without editing the file:

```shell
FeatureManagement__NewCheckout=true dotnet run --project samples/OpenApiFeatureFlags.AspNetCore.Sample --urls http://localhost:5183
```

The XML documentation comments carry inline `<gate>` tags as written. Unlike NSwag, this engine's
reader keeps them intact; the escape NSwag needs is not required here
([`docs/nswag.md`](../../docs/nswag.md) records the difference).

## One thing this engine cannot do

A minimal API's **parameter** cannot be gated: its endpoint metadata carries no `ParameterInfo` to
match on, so only whole operations can be gated for minimal endpoints. A controller parameter gates
normally, as `GET /api/orders/search` shows. [`docs/aspnetcore.md`](../../docs/aspnetcore.md)
records the limitation, and the NSwag sample shows the same API where it does work.
